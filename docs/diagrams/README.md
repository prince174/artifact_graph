# Схемы Artifact Graph

Здесь хранятся отдельные схемы архитектуры и работы сервиса.
Это документация, а не мониторинг: актуальные репозитории и билды смотрите
в веб-интерфейсе запущенного Artifact Graph.

## Редактируемая схема draw.io

Файл: [service-architecture.drawio](service-architecture.drawio).
Откройте его в draw.io Desktop либо импортируйте в diagrams.net.
В файле две страницы:

- **Потоки данных** — чтение Bitbucket Cloud/Data Center и TeamCity,
  сопоставление репозиториев с конфигурациями, анализ push/SBOM, PostgreSQL,
  API, интерфейс и опциональные registry/webhook-интеграции.
- **Kubernetes production** — одна реплика без HPA, Ingress/Service,
  внешние BB/TC/PostgreSQL, Secrets и CA, migration Job и восстановление Pod.

## Интерактивная HTML-карта

Файл: [service-architecture.html](service-architecture.html).
Скачайте или откройте локальный файл в современном браузере. Сервер, доступ
к BB/TC и внешние CDN не требуются. GitHub показывает исходный HTML, а не
интерактивную страницу.

- Кнопки сверху выделяют сценарии обновления, поиска, push, SBOM и отказа upstream.
- Поиск оставляет карточки, в тексте которых есть введённая строка.
- Клик по карточке или Enter/пробел при фокусе открывает описание компонента.
- Esc или клик по пустому месту схемы сбрасывает выделение.
- Ссылка внутри HTML открывает соседний draw.io-файл: сохраняйте оба файла вместе.

Оба формата поддерживаются вручную; изменение draw.io не обновляет HTML автоматически.
При изменении архитектуры актуализируйте обе схемы и проверьте ссылки и тесты.
Не добавляйте в схемы реальные токены, пароли или другие секреты.
